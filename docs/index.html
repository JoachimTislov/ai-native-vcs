Core idea

Making the real work visible instead of exposing raw internals.

Modern engineering teams do not deal with just “one repository.” They deal with two maintained processes that must stay aligned:

Workflow layer

The evolving design process: specs, context, intent, agent work, review, and session history.

Production layer

The real implementation that must remain operational, testable, and releasable in the real world.

The broker creates a stable abstraction between them. It exposes intent, validation, and traceability without forcing users to reason in terms of Git plumbing or ad hoc operational mechanics.

Architecture

Four layers of a coherent AI-native workflow

01

Workflow layer

Sessions, specs, task execution, intent tracking, and actor context.

02

Review layer

Validation, ambiguity handling, regression detection, and evidence-based feedback.

03

Broker layer

The generic double interface that mediates between the active workflow and the maintained implementation.

04

Runtime layer

The concrete system that builds, tests, and ships software in production.

Design principles

AI is a collaborator in a structured process, not a hidden replacement for it.

  • Specs and tasks stay explicit rather than buried in prompts.
  • Validation remains deterministic, reviewable, and test-driven.
  • Session history is the durable record of intent and evolution.
  • Git remains a storage and transport substrate, not the user-facing model.
  • The project stays provider-neutral so the workflow remains portable.
